# MultiDoc / Vistella 全项目代码审计 — 审查规范 (RUBRIC)

> 本文件是所有模块审查员共用的输出规范。严格按此格式产出，Lead 才能机械合并成最终报告。

## 0. 项目背景

- **产品定位**：Qt6 仿 Photoshop 的修图软件（当前实际是"图像编辑器 + 多文档外壳 + 面板系统"）
- **技术栈**：Qt 6.11.1 Widgets（+ Quick 仅启动屏）+ OpenCV 4.12 + LibRaw + lcms2 + spdlog；MSVC2022；CMake
- **规模**：`src/` 350 个文件 / 约 53,000 行；`tests/` 79 个 QTest 文件（**本次不审查**）
- **本次目标（用户原话）**：完整过一遍 code（除 test），整理出
  1. 有哪些问题 / 缺陷（bug）
  2. 哪些是 Qt 本身局限性无法完成的
  3. 哪些 Qt 本身就能实现、或引入第三方库就能完美实现的
  4. 有哪些是代码层面的设计问题
  5. 尽可能详细，并在能解决的同时给出解决建议

## 1. 审查纪律

- 只审查分配给你的文件清单。需要读清单外文件作上下文时可以读，但结论聚焦本模块。
- `tests/` **不审查**。可以翻测试用例来佐证"预期行为应该是什么"，但不要把测试代码本身当审查对象。
- **禁止修改 `src/` 下任何文件**。你只写自己的报告文件（`audit/modules/NN-*.md`）。
- 每条缺陷必须基于你**真实读过**的代码；行号必须准确（`file.cpp:123`）。不确定的标 `[待确认]` 并说明原因。
- 不要臆造 Qt API 行为、PS 行为。拿不准的用 `web_search` 查证，或标 `[待确认]`。
- 不要只读头文件就下结论；关键路径要读实现。
- 报告用**中文**写（代码/标识符/API 保留原文）。

## 5. 设计问题

不是具体 bug，而是结构性问题。逐条写：现象 → 后果 → 建议。

- 线程模型（谁在哪个线程、共享数据、取消机制、背压）
- 性能（大图内存、clone 次数、刷新频率、阻塞 UI）
- 抽象层次（一个类职责过多、重复实现、复制粘贴）
- 可测试性（依赖注入、全局单例、可 mock）
- 异常安全、错误处理（返回值被忽略、Result 类型未统一）
- 命名 / 注释/ 目录组织

## 5. 重点排查清单（每项都要主动过一遍）

1. **指针与生命周期**：空指针解引用、悬垂指针、`QPointer` 用错、Qt parent 变化、`unique_ptr` + Qt parent 双所有权、`delete ui` 顺序、`friend` 类越权访问。
2. **内存**：`new` 无 parent 无 delete、`malloc/free` 不配对、`cv::Mat` 隐式共享误用、大图 clone 次数、缓存无上限、信号槽未断开导致对象复活。
3. **逻辑**：未初始化成员（`bool m_x;` 不初始化）、整数溢出、索引越界、off-by-one、隐式 `int`/`double` 截断、早退路径漏 emit、`if/else` 分支漏赋值。
4. **状态同步**：同一状态在多个类里各存一份（tool/dock/layer/selection/mask/theme）、只更新一份、初始化顺序依赖。
5. **信号槽**：重复 connect、跨线程 `DirectConnection`、connect 失败未检查、对象析构后 emit、lambda 捕获裸指针。
6. **撤销栈**：命令里持裸指针、命令生命周期、redo 后状态不一致、mergeWith 实现错误、内存无上限。
7. **线程**：共享数据加锁、UI 线程阻塞、QObject 在错误线程创建、取消/超时、`invokeMethod` 的线程与生命周期。
8. **坐标**：scene/view/image/device 坐标互转、缩放、DPI、图像原点（左上 vs 中心）、`QTransform` 顺序。
9. **文件 IO**：覆盖确认、异常路径、扩展名/编码（UTF-8/中文路径）、大文件内存、保存丢失 alpha/ICC/元数据。
10. **i18n**：硬编码中英文、`tr()` 缺失/未加 `QObject` 上下文、`.ts` 与源码不同步。
11. **UI**：硬编码尺寸/颜色、QSS 全局污染、无进度反馈、快捷键冲突、无禁用态、焦点问题。
12. **与 PS 交互逻辑差异**：同样的操作 PS 的用户预期是什么，本项目偏离是否会让用户困惑。
